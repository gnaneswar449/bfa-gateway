Active ABAC Security Policies

All policies are enforced centrally by the BFA Policy Engine before any microservice call is executed.

POL_001

User Profile Data Isolation

Students can only view their own profile and timetable. Cross-user access is blocked at the BFA gateway before reaching the User Microservice.

Subject: Student · Action: get_user_profile, get_user_timetable · Condition: targetId == caller.id
POL_002

Room Booking Ownership Enforcement

Only the booking owner or an Admin can cancel a room reservation. BFA verifies ownership before forwarding cancellation to RoomService.

Subject: Any · Action: cancel_room_reservation · Condition: booking.userId == caller.id OR role == Admin
POL_003

Faculty-Only Lab Equipment Orders

Restricted lab equipment (oscilloscopes, logic analyzers) can only be ordered by Faculty or Admin users. Student attempts are blocked immediately.

Subject: Non-Faculty · Action: place_supply_order · Target: Restricted Item IDs
POL_004

Bulk Order Quantity Limit

No single agent transaction may order more than 10 items at once to prevent resource abuse and budget overruns from AI hallucinations.

Subject: Non-Admin · Action: place_supply_order · Condition: quantity <= 10
POL_005

Order Status Ownership Check

Order status queries are scoped to the authenticated caller. Agents cannot retrieve order details belonging to other users without Admin privilege.

Subject: Any · Action: check_order_status · Condition: order.userId == caller.id OR role == Admin
RATE_001

Sliding Window Rate Limiter

Each user/agent pair is throttled to a maximum of 5 tool calls per 10-second window. Prevents recursive LLM loops and denial-of-service conditions.

Window: 10,000 ms · Max: 5 requests · Scope: All registered tools
